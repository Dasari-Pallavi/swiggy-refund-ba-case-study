# Swiggy Order Refund Management System — Mini BRD Case Study

## 📌 Project Overview
This repository features a comprehensive Business Requirements Document (BRD) and operational workflow design analyzing **Swiggy’s Order Cancellation & Refund Journey**. The project focuses on transforming a high-friction, manually intensive support process into an **Automated Instant Resolution System** governed by risk criteria and real-time ledger distributions.

This case study models clear **Business Analyst capabilities**, showcasing process mapping, core operational metrics, functional system requirements, user stories with acceptance criteria, and technical project delivery tracking frameworks.

---

## 🚀 Key Frameworks Covered

### 1. Business Metrics & Target Gains
* **Average Handling Time (AHT):** Targeted to drop from **9.5 minutes to < 1.5 minutes**.
* **First Contact Resolution (FCR):** Target increase from **62% baseline to > 88%**.
* **Operational Savings:** Designed to scale down manual customer support load overheads by **35%**.

### 2. Core Feature Automation Rules
* **Itemized Invoice Selection:** Allows consumers to flag specific missing items instead of blocking whole order items.
* **Smart Account Health Layer:** Automates dynamic lookups to isolate and flag users displaying suspicious refund claim frequencies.
* **Instant Wallet Settlement:** Connects verified safe disputes to direct financial ledger systems within 15 seconds.
